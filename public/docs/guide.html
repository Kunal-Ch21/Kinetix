Native 2D AI motion, vector & character animation — 100% offline. This guide is generated from the same source as the in-app Docs hub.

1. Model Setup

Live in this build

Kinetix Studio never lets a language model draw pixels. The local model is a stateless, amnesic translator: it turns one sentence into a short JSON list of ops, and deterministic native code does every piece of math, rigging, morphing and rendering.

Choosing a model

  • Low-End / Ultra-Fast (4–8 GB RAM, CPU): qwen2.5:1.5b (~1.1 GB).
  • Balanced – recommended (Ryzen 7 7735HS, 16 GB, Radeon 680M): llama3.2:3b Q4_K_M (~2.0 GB).
  • High Precision (32 GB RAM / dedicated GPU): qwen2.5-coder:7b (~4.7 GB).
  • Bring your own: Settings → AI Engine → Browse .gguf; the app writes a Modelfile and registers it with Ollama for you.
TipNo model installed yet? Everything in this guide still works: the Director console in the left dock accepts the same JSON ops the model would produce, and every Cookbook recipe below is exactly that JSON.

Why prompts stay tiny

Each request is two messages only: compact rules + a filtered micro-context (the cast roster, the selected object's blueprint, the keyframe at the playhead) + your sentence. History is never sent, so a project with 10,000 keyframes costs the same ~100 tokens as an empty one.

2. Freehand & Bézier Drawing

Live in this build

Every shape in a scene is a list of cubic Bézier segments in a resolution-independent 0–100 grid (origin top-left). That is what makes morphing, rigging and export exact.

Tools

  • Freehand Brush – smooths your stroke into clean cubic Béziers (adjustable smoothing, width, taper).
  • Pen / Node editor – click-drag anchors and tangent handles to sculpt any silhouette.
  • Parametric shapes – rect, circle, ellipse, star, polygon, line, or any svg_path string.
  • Convert to Bézier Path (right-click) turns any shape into editable nodes, ready to be a morph target.

Writing a path by hand

{ "op": "create_shape", "label": "Leaf", "shape": "svg_path",
  "svg_path": "M0,-10 C8,-6 8,6 0,10 C-8,6 -8,-6 0,-10 Z",
  "x": 50, "y": 50, "fill": "#22C55E" }
TipPaths use local units centred on (0,0). One unit is 1% of the stage width, so a shape 20 units wide always covers a fifth of the frame at any export size. Arcs (A), quadratics (Q,T) and smooth curves (S) are all converted to cubics automatically.

3. Image Import, Rigging & Clones

Live in this build

Parent-child rigging (attach_part)

Attach any shape, tattoo, limb, armour piece or imported sprite to a parent. The child's dx, dy are local offsets in the parent's geometry space, so it inherits the parent's position, rotation, scale and opacity every frame.

{ "op": "attach_part", "id": "Sword", "parent": "Knight",
  "dx": 6, "dy": 1, "pivot_x": 0, "pivot_y": 4, "rotation": -30 }
  • pivot_x / pivot_y is the point of the child's own geometry that is pinned to the attach point, and the centre of its rotation.
  • Select a part and use Rig & Morph → Parent to re-parent from the inspector. Cycles are rejected.
  • Hiding or fading a parent hides or fades the whole rig.

Clone & Override

clone copies an object and its entire rig subtree, including keyframes, then applies differential overrides – no geometry is rebuilt.

{ "op": "clone", "source": "Robot", "label": "Robot Variant",
  "overrides": { "fill": "#7C2D12", "scale": 1.6 },
  "part_overrides": { "Robot Eye": { "fill": "#F59E0B" } },
  "add_parts": [ { "label": "Antenna", "shape": "line", "length": 5, "dx": 0, "dy": -12, "rotation": 90 } ] }
TipDuplicate lock: creating a shape whose label already exists reuses the existing object instead of making a twin. Pass "force_new": true if you really want a copy.

Image import

PNG, JPG, WebP and SVG files are stored in the project asset folder and indexed with a label, tags and bounding box, so imported art can be animated, tinted, rim-lit, used as a parallax layer, or become a parent for attached parts.

4. Realistic Rim Lighting

Live in this build

Add point, spot and sun lights as scene objects (header → Add Light, or the add_light op). Every object that has a Rim setting then receives a specular crescent on the edge that faces each light, in that light's colour.

How the rim shader works

  • The silhouette is drawn, then an offset copy (shifted away from the light by spread) is erased from it. What survives is a crescent hugging the light-facing edge.
  • A second, thinner, whiter pass adds the specular core. Both passes are composited additively and also written to the bloom buffer.
  • Up to the 3 strongest lights contribute, weighted by intensity, distance falloff and (for spots) the beam cone.

Object lighting controls

  • Rim intensity / spread / use light colour – set a fixed colour, or let each light tint its own rim for dual cyan + amber looks.
  • Lit – diffuse light wash clipped to the silhouette.
  • Cast shadow – soft shadow thrown away from the key light (auto), or fixed offset.
  • Ambient occlusion – a soft contact-darkening pool beneath the object.
  • Glow – emissive output into the multi-pass bloom.
  • Depth – 0 near … 1 far. Far objects pick up atmospheric haze and, with Depth of field on, blur away from the focus plane.

Volumetrics

Turn on Volumetric on a light for god-rays and halo (point), a visible beam cone (spot) or a broad atmospheric wash (sun).

{ "op": "set_rim", "id": "Peregrine Falcon", "color": "#06B6D4",
  "light_color": true, "intensity": 1.2, "spread": 0.9 }
TipLight properties are animatable: keyframe intensity, x, y, radius or angle on a light to make a flash, a sunset or a sweeping searchlight.

5. Timeline, Curves & Morphing

Live in this build

Keyframes & the dope sheet

Every animatable property (x, y, rotation, scale, opacity, morph, glow, rim) has a track of amber diamonds. Drag a diamond to retime it, click to select it, right-click to delete or choose an easing. Dragging an object on the canvas writes a keyframe at the playhead when that property is already animated.

Cubic-Bézier curve editor

Select a keyframe, open the Curve tab, and drag the two handles. The curve shapes the motion leaving that keyframe. Values above 1 or below 0 overshoot – that is how springs and anticipation are made. Presets: linear, ease-in, ease-out, ease-in-out, back-out, snap.

Parametric presets

  • linear_move, ease_in_out, spring_bounce – move to to_x,to_y (or dx,dy).
  • arc_jump – parabolic hop with height.
  • walk_cycle – steps, distance, bob, sway.
  • orbit – radius, turns, optional center_x/center_y.
  • pulse – amount, count. shake – amplitude, count.
{ "op": "animate", "id": "Ball", "preset": "arc_jump",
  "dx": 30, "height": 20, "start": 1, "duration": 1.2 }

Vector path morphing (morph_to)

Morphing works between any two paths. The engine pairs sub-paths, subdivides the shorter outline until both have the same number of Bézier segments, fixes winding direction, then picks the start-point rotation that minimises travel. Interpolation runs on the control points every frame, so it stays smooth at 60 FPS.

{ "op": "morph_to", "id": "Peregrine Falcon", "target": "Shadow Beast",
  "at": 3.5, "duration": 2, "ease": [0.65, 0, 0.35, 1] }
Tiptarget may be another object (its path and colour are used), or an inline spec such as { "shape": "star", "outer": 12 }, or { "svg_path": "M…" }. The object's fill → fill-to colours cross-fade with the morph.

Relative modifiers

Never ask the model to do arithmetic. Use { "op": "speed", "id": "Ball", "speed_multiplier": 2 } or keyframe with "modifier": "add" | "multiply" – exact values are computed in code.

6. Kinetic Type, Environments & Particles

Live in this build

Kinetic typography

Text splits into characters or words, each delayed by stagger seconds. Effects: rise, fade, pop (spring), drop (bounce), spin, wave (continuous), typewriter. Text objects support fill, glow, rim lighting, keyframes and parenting like any other object.

{ "op": "add_text", "content": "HELLO", "effect": "pop", "unit": "char",
  "stagger": 0.08, "start": 0.5, "size": 9, "x": 50, "y": 45 }

Procedural backgrounds

set_background loads a full procedural world: multi-stop sky gradient, sun/moon glow, twinkling stars, drifting volumetric clouds, three-layer parallax mountains, horizon haze, depth-of-field and vignette. Presets: dusk, night, dawn, storm, day, none. Every value is editable in the World tab.

Particle emitters

Kinds: embers, sparks, mist, rain, snow, trail. A trail emitter with follow leaves particles where the object was, so it always matches the motion. Particles are a pure function of time, so scrubbing and export are frame-exact.

{ "op": "add_emitter", "kind": "trail", "follow": "Ember Star",
  "color": "#F59E0B", "color2": "#EF4444", "start": 0, "end": 6 }

7. Exporting: MP4, GIF, PNG, SVG, JSON

Live in this build

Export (top-right) renders your project frame by frame with the same renderer the viewport uses — no screen capture. Frame i is drawn at t = i ÷ fps, so the same project always produces the same pixels, at any resolution, on any machine.

Formats

  • MP4 (H.264) — yuv420p, BT.709, +faststart, CRF quality (default 18, preset veryfast). Frames are streamed straight into FFmpeg, so a 10-minute 4K export never holds more than one frame in memory.
  • GIF — palette-optimised with FFmpeg palettegen + paletteuse (Bayer dithering). GIF stores delays in 1/100 s, so 60 fps plays at about 50 fps; 24–30 fps is the sweet spot.
  • PNG sequence — one numbered file per frame (frame_0000.png, frame_0001.png …) into a folder you choose. The numbers are the real frame indices, so exporting 2.5 s–4 s at 30 fps starts at frame_0075.png. Works without FFmpeg.
  • SVG — a resolution-independent vector snapshot at the playhead (rig transforms, keyframes, morphs, gradients, shadows and sprites). Bloom, volumetric light and particles are raster effects and are not included.
  • Scene JSON — the complete project (objects, rig, keyframes, lights, emitters, story events) as .kinetix.json.
  • PNG still — the current playhead frame at the chosen resolution.

Resolution, frame rate and range

  • 720p / 1080p keep your scene's aspect ratio (height fixed, width derived and rounded to an even number — H.264 requires even sizes). Custom accepts any size up to 7680 × 4320.
  • 24 / 30 / 60 fps. The range is [start, end) in seconds — the end is exclusive, so a 10 s project at 60 fps is exactly 600 frames. From playhead starts the export where you are parked.
  • Because the scene lives on a 0–100 grid, changing resolution never changes the composition.

Where the file goes

Press Browse… (or just Export) to pick a file with the native save dialog — or a folder for PNG sequences. Videos are written to <name>.part and renamed only when FFmpeg finishes cleanly, so a failed or cancelled export never leaves a half-written video.

Progress, cancel and errors

  • The progress panel shows frame x / N, ETA, elapsed time and MB written.
  • Cancel export stops immediately: FFmpeg is killed and every temporary and partial file is deleted. Closing the app mid-export does the same.
  • Disk full and permission denied are reported in plain language (for example “Disk full while writing …”) and partial files are cleaned up — free some space or pick another drive and try again.

FFmpeg

MP4 and GIF are encoded by FFmpeg. Kinetix looks for it in this order: the KINETIX_FFMPEG environment variable → a copy bundled next to the app (the sidecar in installer builds) → ffmpeg on your PATH.

winget install Gyan.FFmpeg      # Windows
sudo apt install ffmpeg         # Debian / Ubuntu
brew install ffmpeg             # macOS
TipNo FFmpeg? The Export dialog says so clearly and keeps PNG sequence, SVG, Scene JSON and PNG still fully usable. You can turn a PNG sequence into a video later with any editor.
TipDevelopers: npm run tauri:build:bundled stages FFmpeg as a Tauri sidecar (externalBin) so the installer ships it. See the README, section Build & package.

9. JSON Op Reference

Live in this build
  • create_shape · create_assembly · attach_part · detach_part · clone · delete
  • morph_to · animate · keyframe · speed
  • set_rim · set_shadow · set_style · add_light
  • add_text · add_emitter · set_background · story_event

Objects are referenced by id, label or alias (fuzzy). Unknown ops and bad references are reported in the console log and never corrupt the scene. Every run is one undo step (Ctrl+Z).

[
  { "op": "add_light", "type": "spot", "x": 30, "y": 8, "angle": 70, "cone": 24, "color": "#F59E0B" },
  { "op": "story_event", "start": 0, "end": 3, "title": "Spotlight enters" }
